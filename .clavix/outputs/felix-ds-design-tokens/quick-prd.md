# felix-ds design-token export (DTCG) – Quick PRD

felix-ds theme values live only as CSS custom properties in composed SCSS, forcing design-tool and non-CSS consumers to hand-copy values with nothing keeping them honest. Build a one-way, reproducible export of the full composed theme (upstream `@fkui/theme-default` plus felix overrides, light and dark modes) as W3C DTCG-format JSON: `scripts/tokens.ts` (bun) compiles both colour-mode mixins via sass, classifies each emitted custom property by DTCG `$type`, and writes complete, self-contained `tokens/light.json` and `tokens/dark.json` that are committed to the repo and shipped in the npm package. A `bun test` parity suite verifies the JSON against freshly compiled CSS (names, values, alias resolution, structure) and fails if the committed files are stale or a value cannot be typed. The consumer is tool-agnostic: any DTCG-capable tool, no tool-specific concessions.

No new dependencies or build tools – bun and the existing sass compiler only; DTCG JSON is emitted by the script itself. SCSS stays the single source of truth. The token universe is whatever the composed `light`/`dark` mixins actually emit (discovered by compiling, not a maintained list); the only exclusion is the two `--f-logo-image-*` url() tokens; anything unclassifiable fails the build. Type mapping: colors, dimensions, fontFamily stacks, fontWeight numbers, unitless line-height numbers, composite shadows (with `none` shadows kept as a documented `"none"` deviation). The two `var()` aliases become DTCG alias references, including part-aliases inside the focus-shadow composite. Naming mirrors custom-property names hyphen-split into groups under `f`/`fkds`, making round-trip mechanical. Packaging adds `tokens` to `files`, a README section, and bilingual `docs/tokens.{en,sv}.md`; release is an owner-gated 1.0.1 → 1.1.0 bump via the existing runbook.

Out of scope: reverse import (DTCG → SCSS), Style Dictionary configs, Figma/Tokens Studio publishing automation, migrating the playground/demo/consumer sites, composite heading-typography tokens (skipped in v1 by owner decision), bulk `$description` authoring, and any theming scheme beyond the two complete per-mode files. The four process exclusions were proposed defaults adopted 2026-10-05 after the owner skipped the confirmation question – they exclude work only and are trivially reversible by editing the PRD.
