# Security policy

## Supported versions

The latest minor of the 1.x line receives security fixes, matching the
support policy in [docs/governance.en.md](./docs/governance.en.md). Older
minors receive no patches – upgrade per the release notes.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on this repository (Security
tab → Report a vulnerability). Do not open a public issue for something you
believe is exploitable. You can expect an initial response within a week;
the fix, if accepted, ships in the next patch or minor and is credited in
its release notes unless you prefer otherwise.

## Scope

The published package ships stylesheets (prebuilt `dist/*.css` and SCSS
sources), font files, DTCG token files and one optional TypeScript module
(the icon spritesheet). There are no runtime server components and no
executable install scripts. The realistic attack surfaces are:

- the repository's build and test tooling (dev dependencies: vite, sass,
  playwright, bun itself), and
- the CI workflows in `.github/workflows/`.

## What is in place

- **Tag-triggered releases only.** Publishing happens in one documented
  workflow (`release.yml`) that fires exclusively on a `v*` tag pushed by
  the owner, with the minimal permissions it needs (`contents: write`,
  `packages: write`).
- **SHA-pinned third-party actions.** Every external action in every
  workflow is pinned to a full commit SHA, with the release tag it was
  resolved from noted in a comment. A moved or mutated tag cannot inject
  code into CI; upgrading an action is a deliberate diff.
- **Pinned runner image.** All workflows run on `ubuntu-24.04` – the image
  the committed visual baselines were rendered on – so CI cannot silently
  drift to a different operating system.
- **Weekly dependency audit.** `bun audit` runs in the FKUI-currency
  workflow on the latest pin. It is deliberately report-only
  (`continue-on-error`): the published package has no runtime dependency
  tree, so an advisory in dev-only tooling must be visible but should not
  freeze the FKUI bump flow. Remediation is `bun audit fix` (or a pin
  bump) in an ordinary reviewed change.
- **Parity gates.** `bun test` fails any committed `dist/` or `tokens/`
  file that no longer matches its SCSS source, so a tampered or stale
  artefact cannot be published unnoticed. The release also re-runs the
  full visual and axe gates before publishing.
- **Consumers pin exact versions.** Consumers install a version they
  choose and pin it themselves; the package's only peer dependency is
  `@fkui/theme-default` inside the range documented in the governance
  policy.

## Provenance

npm provenance (Sigstore attestations) is not applicable while the package
publishes to GitHub Packages rather than the public npm registry:
provenance is generated by npm only for publishes to the public registry.
If distribution ever moves there (an owner decision, out of scope for the
current proof of concept), the release workflow should enable it
(`id-token: write` permission plus npm's provenance flag) and this section
replaces itself.

## Dependency scanning

Dependabot is not configured: its support for the bun lockfile is not
complete enough to rely on, and the weekly `bun audit` step covers
advisory checking for the dependency tree. Revisit if Dependabot gains
full bun support.
